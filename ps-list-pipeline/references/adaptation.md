# 用当前手机证据适配

使用条件：默认试采出现裁图/页面边界偏移，或换了 App 版本、字体、显示缩放。先看整屏截图与 XML；仅改变分辨率并不一定需要配置。

## 坐标约定

`inspect_page.ps1` 读取实际截图尺寸 W×H。归一化比例 s=1272/W，所有 x、y 坐标都乘同一个 s，不能把 y 单独按 H/2772 拉伸。实际高度归一化为 H×s；列中线是 636。`nodes-reference.json` 已完成换算，可直接对照使用。

只有确认仍是竖屏双列时才套用列规则。单列、三列、平板侧栏或不同语义结构，不能仅靠缩放修复；先切到用户允许的双列展示，或为该布局实现独立解析并试采验证。

## 布局文件

JSON 是数据，不执行代码。保存在本次任务目录，使用 `-LayoutFile` 显式传入试采和正式采集。示例数值是原布局的起点，必须按当前证据调整：

```json
{
  "schemaVersion": 1,
  "app": "xhs",
  "screenWidth": 1080,
  "screenHeight": 2400,
  "layout": {
    "headerY": 600,
    "left": [52, 593],
    "right": [679, 1220],
    "gap": 4
  }
}
```

`screenWidth/screenHeight` 必须填写实际截图尺寸；`layout` 内的数值必须使用归一化坐标，不能混用。平台/屏幕不匹配会报错。

- `headerY`：搜索框、页签及筛选条的下边界，用来排除顶部遮挡。
- `left/right`：左右商品图片的横向范围，各为 `[x1,x2]`，不能包括相邻列。
- `gap`：标题上沿到图片下沿的保守留白。小红书存在评价行时，程序仍优先排除评价行。
- 可选 `minH/minLen/maxLen`：标题候选框的最小高度、标题字符长度范围。只有证据证明默认过滤不合适时才改，不要为追求数量放开全部标签。

边界偏移用布局文件修正；评价/促销误识别、店铺/价格归属错误属于语义问题，需要修正 `list_core.ps1` 并增加与当前 XML 相符的回归证据。设备配置不能修复 XML 根本没提供的字段。

## 验证与恢复

1. 对同屏 XML/PNG 离线回放：把同名 `.xml/.png` 文件放在只含商品页的目录，用 `ps_collect.ps1 -ReplayDir <目录> -LayoutFile <配置> ...`。横向位置、裁剪和字段对应均需检查。
2. 实机试采 3 条。后续需要滚动采集时还需检查一次滚动后的页面；若 3 条全在首屏，可额外滚动一屏捕获证据并离线核查。检查顶部半卡、右列浮层、重复或串列，不能用满 3 条就代替滚动验证。
3. 正式采集沿用同一配置。若页面结构中途变化，保留检查点，重新采集证据后判断是否还能续采。

本地配置只代表当前设备/布局。不要将设备地址或真实页面数据当作公共样例上传，也不要宣称通过某个模拟分辨率就适配了所有同分辨率手机。
